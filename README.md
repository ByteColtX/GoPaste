# GoPaste

局域网直连的剪贴板历史工具，用 Go 和 [MyGo](https://mygo.egoist.dev) 写原生界面。

![GoPaste 主界面：左侧筛选栏、中间历史列表、右侧代码预览](docs/images/main-window.png)

*这张图是用示例数据跑出来的，历史记录是假的；侧栏的设备列表与"已同步"标记来自真实的同步状态。*

## 设计约束

下面三条是硬约束，不是待办事项：

- **只走局域网直连。** 没有内置中继、云服务、第三方代理，也没有任何非局域网的回退连接。
- **剪贴板内容不出本机。** 不写普通日志，不做遥测，不发给任何第三方服务。
- **原生界面。** 保持 MyGo 原生窗口和控件，不引入 WebView 或独立前端框架。

## 当前状态

剪贴板捕获、本地历史、界面和局域网同步都已经能用：同网段的两台设备配对之后，在一台上复制的内容会自动出现在另一台的剪贴板和历史里。

- 首次启动向导：给这台设备起个名字；已经在另一台设备上用过的，向导直接指向设备页的配对
- 剪贴板监听，自动区分文本、富文本、图片、文件和代码片段；用内容摘要当 ID，同样的内容不会存两份
- 跳过密码管理器标记的敏感内容，不记进历史
- 本地 SQLite 历史，写入排队执行，退出时不丢刚复制的那条
- 搜索、按类型 / 标签 / 来源筛选、收藏、删除、撤销
- 预览图片、文件路径和代码语法高亮（chroma）
- 系统托盘、窗口快捷键、界面缩放
- 简体中文 / English 双语，跟随系统或手动固定；浅色 / 深色 / 跟随系统
- 局域网发现、6 位配对码配对、按内容类型分别设置的同步方向，以及每条记录的投递状态与重发

## 局域网同步

两台设备都打开 GoPaste、连在同一个局域网里，它们会互相发现：

1. 在设备页点「+」打开配对对话框，选中对方，本机显示一个 6 位配对码。
2. 在对方设备上输入这个码，配对完成；双方各自把对方的公钥记下来。
3. 之后在任一台设备上复制，内容会直接送到另一台：写进它的剪贴板，也进它的历史（标记来源设备）。

发现同时走两条路：标准 mDNS（`_gopaste._tcp`）和 UDP 广播（47824）。两条路报的是同一份设备信息，哪条先听到就用哪条。这么做是因为 mDNS 并非在所有网络上都能用：实测一台有线 Windows 和一台无线 Mac 在同一网段时，路由器把 224.0.0.0/24 的组播单向过滤掉了——有线发往无线的 mDNS 全部丢失，而普通子网广播照常通过。只依赖 mDNS 的话，那台机器上永远发现不了对方。

传输只用局域网直连：TLS 1.3 双向认证，双方各自钉住对方的公钥，没有证书颁发机构、没有中继、没有云端。配对码由两边的临时密钥派生，中间人改了密钥就算不出同一个码。

设备页可以为每台设备单独关掉同步，也可以按文本、图片、文件、富文本分别设置双向 / 仅发送 / 仅接收 / 不同步。接收端自己的设置同样生效：设成「仅发送」的设备不会收内容。

已知限制：**文件项只同步路径文本，不传文件内容**——另一台设备拿到的是那串路径，文件本身还在原来的机器上。跨机器传文件是另一个功能。

配对信息与私钥放在用户数据目录下的 `devices.json`（权限 0600）：macOS 是 `~/Library/Application Support/GoPaste/devices.json`，Windows 是 `%LOCALAPPDATA%\GoPaste\devices.json`。它和历史数据库放在一起，不进仓库、不上传。监听端口默认 47823，被占用时退到临时端口，实际端口随广播带出去。

Windows 上第一次使用时，系统防火墙可能会拦下入站连接：允许 GoPaste，或放行 TCP 47823 与 UDP 47824。

## 运行

需要 Go 1.27.1 或更高版本。

```sh
go run .              # 直接运行
go tool mygo dev      # 开发模式，带热重载
go tool mygo build    # 打包，macOS 产出 .app 和 .dmg
```

想先看看界面长什么样，运行 `scripts/preview.sh`：它先用 `scripts/mockdb` 造一批示例历史，再启动开发版应用。示例数据只写在本机 `.preview/history.db`，不会提交到仓库；预览构建（`-tags preview`）不监听剪贴板，所以走查时复制的东西不会混进示例数据。预览图片需要自己放进 `.preview/images/`（第三方照片不进仓库），缺图时生成器会直接报错。

历史数据库默认放在用户数据目录下，macOS 是 `~/Library/Application Support/GoPaste/history.db`。`-db PATH` 或 `GOPASTE_HISTORY_DB` 可以改到别处，路径必须是绝对路径；应用启动的第一行日志会报出它实际用的文件。

同一个目录下还有一个 `settings.json`，只存跨启动需要记住的少量选择：首次启动向导是否已完成、用户改过的设备名、用户改过的历史保留上限。删掉它，下次启动就会重新走一遍向导。语言、外观这些界面选择目前仍只在本次运行内有效。

## 开发

```sh
go fmt ./...
go tool mygo vet .
CGO_ENABLED=0 go test ./...
```

`internal/` 下的包不依赖 MyGo，可以脱离界面单独测试（`internal/lansync` 是唯一碰网络的包）。两台机器的真实同步另有需要手动开启的测试，用法见 `internal/lansync/live_test.go`（`GOPASTE_LIVE_PEER=1`）：

| 包 | 职责 |
| --- | --- |
| `internal/capture` | 把剪贴板变化变成历史条目：合并一次复制的多次通知、读取、分类、决定是否保留 |
| `internal/lansync` | 局域网这一层：设备身份、mDNS 发现、6 位码配对、钉住公钥的 TLS 连接、投递与重发 |
| `internal/clipboard` | 唯一直接调用剪贴板库的地方，负责处理各平台格式不一样的问题 |
| `internal/history` | 历史数据与用户可见的操作，含筛选、排序、自动清理、条目 ID 的内容摘要，以及每条记录发给了哪些设备 |
| `internal/history/sqlite` | `history.Repository` 的 SQLite 实现，纯 Go 驱动，CGO 关闭也能构建 |
| `internal/syntax` | 猜代码片段是什么语言，再用 chroma 切成一段段好上色 |
| `internal/filetype` | 按文件名判断类型，决定图标、颜色和标签 |

平台相关代码集中在 `tray.go`、`persistence.go`、`runtime.go` 和 `state.go`。
