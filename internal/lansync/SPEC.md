# 局域网同步

## 职责

同一局域网内的两台 GoPaste 之间唯一的网络层：本机身份、互相发现、一次性配对、
把剪贴板内容直接送到已配对设备，并把投递结果如实报回界面。

它是应用里唯一碰网络的包。界面只通过 `Service` 使用它：`Devices` / `Peers` /
`Pair` / `ConfirmPairing` / `Send` / `Resend` / `SetDeviceSync` / `SetDirection` /
`RemoveDevice`，结果全部经 `Options` 里的回调返回。慢活（发现、配对、投递）都在
自己的 goroutine 上，回调也发生在那里——调用方自己负责搬到界面线程。

## 边界

- 依赖 `internal/history`（条目、内容摘要、投递状态）与标准库，加上 mDNS 的实现
  `github.com/hashicorp/mdns`。不依赖 MyGo、不依赖界面、不碰 `history.db`。
- 自己拥有 `devices.json`：本机私钥、设备名与平台、已配对设备的钉住公钥、每台
  设备的同步开关与四种内容类型的方向。
- 不拥有历史记录，也不决定某条内容该不该进历史：收到的内容以 `Clip` 交给调用方，
  由应用决定怎么存、要不要写剪贴板。

## 契约

**身份。** 首次启动生成一对 ed25519 密钥；peer ID 是公钥 SHA-256 前 10 字节的
base32（16 字符），因此重启不变，也不需要单独存 ID。每台设备用这把密钥在内存里
签一张自签名证书，不落盘。

**发现。** 两条路同时走，报的是同一份设备信息，哪条先听到就用哪条：

- mDNS：广播 `_gopaste._tcp`，TXT 带 `id`、`name`、`platform`、`version`、`pk`。
- UDP 广播：每 3 秒向每张网卡的子网广播地址发一条 JSON 公告到 47824，内容同上。

两条路的应答里 `id` 都必须等于公钥导出的 peer ID，否则整条忽略——否则钉住的记录和
设备列表会对不上号。每张「up + 组播 + 非回环 + 有私有 IPv4」的网卡各起一个 mDNS
responder 和一个浏览循环：系统默认组播路由常被 VPN 隧道抢走，按网卡绑定才可靠。
20 秒没消息算离线，80 秒后忘掉；只有界面上看得见的东西变了才回调。

**为什么要两条。** mDNS 依赖 224.0.0.251，而它并非在所有网络上都能用：实测一台有线
Windows 与一台无线 Mac 在同一网段时，路由器把 224.0.0.0/24 从有线到无线单向过滤，
mDNS 全部丢失，普通子网广播却照常通过。只依赖 mDNS 会让那台机器永远发现不了对方。
广播不是 mDNS 的替代品：mDNS 更标准、也能被系统工具看到，能通的时候它就是主路径。

**配对。** 发起方显示 6 位码，响应方在本机输入。码与确认 MAC 由 X25519 共享密钥
加「双方静态公钥 + 双方临时公钥」的记录经 HKDF 派生：中间人在两边各开一段会话就
会算出不同的码，用户输入的码必然对不上。60 秒窗口、单次尝试、同时只接受一个请求。
确认后双方钉住对方公钥。

**传输。** TCP 47823（占用时退到临时端口，广播真实端口），HTTP/1.1 over TLS 1.3。
握手要求客户端证书，但「是否已配对」由请求级中间件判断：配对本身也走这条通道。
客户端在拨号时把地址解析回已配对设备，并要求对方证书公钥正好是钉住的那把；不跟随
重定向。端点只有 `POST /v1/pair/{hello,wait,cancel}` 与 `POST /v1/clip`。

**条目身份。** 载荷按「能算出内容 ID 的形态」（`Clip`）传输，接收端自己用
`history.ContentID` 算 ID，不信任发送端的 ID。同一内容在两台设备上落到同一条记录。

**投递。** 目标是「设备开关打开 + 该内容类型方向允许发送」的设备，并行投递，
结果一次性回报为 `history.DeviceDelivery`：收到 / 离线 / 未送达（对方拒收）。
接收端按自己的方向设置决定收不收。投递失败记入 `unreachable` 并保持离线 20 秒，
避免陈旧的发现记录每几秒把设备翻回在线、反复重试。设备重新上线后由应用补发还没
送到的记录；新内容进来时，一条都没送到的旧记录转为「已替换」，不再自动重试。

**文件项。** 只传路径列表，不传文件内容：接收端存成文件条目、不带预览，文件本身
留在原机器上。

## 不变量

- 只有局域网直连。没有中继、云端、第三方代理，也没有任何非局域网回退；做不到就
  不工作。
- 剪贴板内容不进日志。日志里只有失败原因与文件路径。
- 未配对设备的请求只能打到配对端点；其余端点一律 403。
- 身份文件 0600、原子替换；读不出来时报错且**不覆盖**，配对数据不可重建。

## 明确不做

- 跨机器传文件内容。
- 密钥轮换、多网卡优先级手动选择、设备重命名（改名靠设备自己广播新名字）。
